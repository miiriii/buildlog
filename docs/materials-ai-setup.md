# 학습 자료함 자동 AI 요약 실행 안내

최종 확인일: 2026-10-25. 기존 React + FastAPI + Supabase PostgreSQL과 쿠키 로그인을 사용합니다.

## 1. 입력할 값

**프로젝트의 `backend/.env`**에 다음 항목만 추가하고 등호 뒤에 본인의 OpenAI API 키를 입력하세요. 프로젝트 바로 아래 `.env`가 아닙니다. 기존 DB·로그인 설정은 유지하세요.

```dotenv
OPENAI_API_KEY=
```

실제 키는 이 문서나 `.env.example`, 프론트 코드에 적지 않습니다. 서버에서만 사용하며 `.env`와 업로드 파일은 Git에서 제외됩니다. 이번 작업에서 실제 `.env`는 수정하지 않았습니다.

모델·프롬프트·영상 처리·내부 작업자에는 추가 필수 설정이 없습니다. 기본 모델은 `gpt-6-luna`입니다. OpenAI SDK 3.37.0, PyAV 19.0.2, psutil 7.2.2를 현재 백엔드 가상환경에 설치하고 requirements에 고정했습니다. Windows에서 별도 FFmpeg 프로그램·경로 설정, Redis나 워커 터미널이 필요하지 않습니다. 다른 컴퓨터에서는 `python -m pip install -r requirements.txt`로 설치합니다.

## 2. 실행

이미 실행한 백엔드는 해당 터미널에서 Ctrl+C로 종료한 뒤 **backend 폴더**에서 실행합니다.

```powershell
.\.venv\Scripts\python.exe run.py
```

미적용 Alembic 변경을 먼저 적용한 다음 `127.0.0.1:8000`에서 개발 서버를 시작합니다. 적용한 변경은 다시 적용하지 않습니다. DB 준비 실패 시 서버를 시작하지 않고 확인할 항목을 안내하며 SQLite로 대체하지 않습니다. 기존 데이터·원본은 삭제하지 않습니다. API 요청이나 app import가 테이블을 만드는 구조는 아닙니다.

이번 작업에서는 기존 연결로 Supabase에 `0003_material_analysis`까지 적용하고 PostgreSQL의 컬럼·head·materials RLS 활성화를 확인했습니다. 새 환경도 같은 명령을 사용하면 됩니다. 테이블만 준비하려면 ` .\.venv\Scripts\python.exe run.py --prepare-only`를 실행합니다.

별도 터미널의 **frontend 폴더**에서 실행합니다. 기존 프론트가 실행 중이면 새로고침하면 됩니다.

```powershell
npm.cmd run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

브라우저에서 `http://localhost:5173/materials`를 열고 기존 계정으로 로그인합니다. 브라우저/API는 기존 `localhost`와 CORS 설정을 유지합니다.

## 3. 확인 순서

1. 제목과 PNG/JPG 이미지 한 개를 선택해 업로드합니다. 원본 저장 성공 후 카드가 요약 대기→분석 중→AI 요약으로 바뀌는지 확인합니다.
2. 새로고침해도 요약이 남는지 확인하고 원본 보기를 누릅니다.
3. 짧은 MP4도 등록합니다. 최대 8장의 대표 화면만 보내며 카드에 화면 수·음성 미포함을 표시합니다. 오디오 추출·전사는 하지 않습니다.
4. 기존 자료는 자동 분석하지 않습니다. 키를 넣기 전에 새로 저장해 분석에 실패한 자료는 서버 재시작 후 ‘다시 요약’으로 요청할 수 있습니다. 과금 가능성을 안내하고 확인한 뒤에만 재시도합니다.

분석 실패는 원본 저장 실패와 다릅니다. 원본 보기·삭제는 요약 중에도 가능합니다. 실패한 분석만 자료당 최대 3번 실행하며 SDK 자동 재시도는 없습니다. 사용자별 대기 2개·처리 중 1개, 프로세스당 한 자료를 처리합니다. 대기 한도 초과 시에도 원본은 저장하고 요약 실패 안내를 표시합니다.

## 4. 문제 확인

| 상황 | 확인할 내용 |
| --- | --- |
| AI 연결 설정 필요 | backend/.env의 OPENAI_API_KEY와 입력 후 백엔드 재시작 여부 |
| 인증 설정 확인 | 유효한 키·프로젝트 권한. 실제 키를 로그·채팅에 붙이지 않기 |
| 모델 접근 설정 확인 | OpenAI 프로젝트의 기본 모델 사용 가능 여부. 비싼 모델로 자동 전환하지 않음 |
| 사용 한도·결제 상태 | OpenAI API 결제·잔액·프로젝트 한도. ChatGPT 이용권과 API 사용은 별개 |
| 시간 초과·연결 불확실 | 원본 유지. 목록 새로 확인 후 필요할 때 재시도. 이전 호출이 과금됐을 가능성 있음 |
| 영상 분석 불가 | 디코딩 가능한 MP4인지 확인. 저장 가능한 컨테이너와 분석 가능한 코덱은 다를 수 있음 |
| DB 준비·자료 목록 실패 | 기존 DATABASE_URL의 Session pooler·5432·URL 인코딩된 DB 비밀번호·SSL·프로젝트/네트워크/권한 |

키 한 항목만 추가하도록 코드·패키지·DB 준비를 끝냈습니다. OpenAI 계정의 API 결제·모델 접근과 인터넷 연결은 필요합니다. AI 요약은 원본과 함께 확인하세요. 이미지/프레임의 외부 OpenAI 전송을 업로드 폼에도 안내합니다. `store=False`를 사용하지만 외부 서비스의 전체 보존 정책을 바꾸는 설정은 아닙니다.

## 5. 검증 범위

- 실제 이미지·MP4 디코딩, 자식 프로세스 제한/정리, SDK 요청·구조화 출력, 안전한 실패 분류를 검증했습니다. 자동 테스트는 가짜 키·모의 응답만 사용합니다.
- 임시 SQLite/업로드 폴더와 실제 Chrome에서 가입·로그인→이미지/영상 저장→모의 AI 요약 표시→새로고침 유지→원본 보기/영상 재생→삭제를 확인했습니다. 1440px/360px에서 가로 넘침이 없었습니다.
- 실제 Supabase 마이그레이션과 컬럼·RLS 활성화는 확인했습니다. Data API의 역할별 접근, 여러 PostgreSQL 작업자의 동시 선점, 실제 사용자 자료 저장은 별도 확인이 필요합니다.
- 실제 키가 없어 **유료 호출·한국어 요약 품질·실제 사용량/청구 금액은 미검증**입니다. 모의 테스트를 실제 모델 응답으로 보고하지 않습니다. Edge·Safari·실제 휴대폰도 미확인입니다.
