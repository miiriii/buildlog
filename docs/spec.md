# BuildLog 기능 동작 설명서

## 1. 문서 목적

이 문서는 `PRD.md`에 정한 BuildLog의 기능이 사용자 입장에서 어떻게 동작해야 하는지 설명합니다.

- PRD에서 정한 조건은 그대로 사용합니다.
- PRD에 없는 기능은 추가하지 않습니다.
- PRD와 이후 대화에서 확정한 세부 규칙을 함께 사용합니다.
- 기술 구현 방법보다 사용자의 행동과 화면에 보이는 결과를 중심으로 설명합니다.

## 2. 회원 기능

### 2.1 회원가입

#### 1) 사용자가 무엇을 입력하거나 누르는지

- 이메일을 입력합니다.
- 비밀번호를 입력합니다.
- 닉네임을 입력합니다.
- 회원가입 버튼을 누릅니다.
- 이메일과 닉네임의 앞뒤 공백은 제거하며 비밀번호는 입력한 그대로 확인합니다.

#### 2) 정상적으로 처리되면 무엇이 저장되고 화면에 무엇이 보이는지

- 이메일, 안전하게 처리된 비밀번호, 닉네임으로 사용자 계정이 만들어집니다.
- 하나의 이메일로는 계정 하나만 만들 수 있습니다.
- 가입한 이메일과 비밀번호로 로그인할 수 있게 됩니다.
- 회원가입에 성공하면 로그인 화면으로 이동합니다.

#### 3) 잘못 입력하거나 처리에 실패하면 어떻게 되는지

- 이미 사용 중인 닉네임은 저장하지 않고 다른 닉네임을 입력하도록 알려줍니다.
- 이미 사용 중인 이메일은 저장하지 않고 다른 이메일을 입력하도록 알려줍니다.
- 일반적인 이메일 주소 형식이 아니면 가입하지 않고 올바른 이메일을 입력하라고 알려줍니다.
- 비밀번호가 8자보다 짧거나 64자를 넘으면 가입하지 않고 길이 조건을 알려줍니다.
- 닉네임이 2~20자가 아니거나 한글, 영문, 숫자, 밑줄 이외의 문자를 포함하면 가입하지 않습니다.
- 회원가입 처리에 실패하면 실패 이유를 알려줍니다. 이메일과 닉네임은 유지하고 비밀번호만 지웁니다.

#### 4) 누가 보거나 수정·삭제할 수 있는지

- 가입 전 사용자가 회원가입 화면을 사용할 수 있습니다.
- 비밀번호는 화면에 그대로 보여주거나 다른 사용자에게 공개하지 않습니다.
- 계정 삭제 기능은 PRD에 없으므로 이 설명서에 포함하지 않습니다.

#### 5) 나중에 제대로 만들었는지 어떻게 확인하면 되는지

- 서로 다른 이메일과 닉네임으로 계정을 만들 수 있는지 확인합니다.
- 같은 이메일로 계정을 두 개 만들 수 없는지 확인합니다.
- 이미 사용 중인 닉네임으로 가입할 수 없는지 확인합니다.
- 잘못된 이메일 형식으로 가입할 수 없는지 확인합니다.
- 비밀번호 8자와 64자는 사용할 수 있고 7자와 65자는 사용할 수 없는지 확인합니다.
- 닉네임 2자와 20자는 사용할 수 있고 범위를 벗어나거나 허용되지 않은 문자가 있으면 가입할 수 없는지 확인합니다.
- 가입 성공 후 로그인 화면으로 이동하는지 확인합니다.
- 가입 실패 시 이메일과 닉네임은 남고 비밀번호만 지워지는지 확인합니다.
- 가입한 정보로 로그인할 수 있는지 확인합니다.
- 이메일 확인 절차가 추가되지 않았는지 확인합니다.

### 2.2 로그인

#### 1) 사용자가 무엇을 입력하거나 누르는지

- 이메일과 비밀번호를 입력합니다.
- 로그인 버튼을 누릅니다.

#### 2) 정상적으로 처리되면 무엇이 저장되고 화면에 무엇이 보이는지

- 입력한 정보가 가입된 계정과 맞으면 로그인 상태가 됩니다.
- 로그인한 사용자는 자신의 기록과 다른 사용자의 공개 기록을 볼 수 있습니다.
- 로그인에 성공하면 내 기록 홈 화면으로 이동합니다.

#### 3) 잘못 입력하거나 처리에 실패하면 어떻게 되는지

- 이메일이나 비밀번호가 맞지 않으면 로그인하지 않습니다.
- 이메일이나 비밀번호가 맞지 않으면 로그인 정보가 맞지 않다고 알려줍니다.
- 로그인 처리 자체에 실패하면 실패 이유를 알려줍니다. 이메일은 유지하고 비밀번호만 지웁니다.

#### 4) 누가 보거나 수정·삭제할 수 있는지

- 로그인한 사용자는 자신의 기록을 만들고 관리할 수 있습니다.
- 로그인한 사용자는 다른 사용자의 공개 기록만 볼 수 있습니다.
- 로그인하지 않은 사용자는 공개 기록을 포함한 기록 화면을 볼 수 없습니다.

#### 5) 나중에 제대로 만들었는지 어떻게 확인하면 되는지

- 올바른 이메일과 비밀번호로 로그인되는지 확인합니다.
- 틀린 정보로 로그인되지 않는지 확인합니다.
- 로그인 성공 후 내 기록 홈 화면으로 이동하는지 확인합니다.
- 로그인 실패 시 이메일은 남고 비밀번호만 지워지는지 확인합니다.
- 로그인하지 않은 상태에서 공개 기록 화면에 접근할 수 없는지 확인합니다.
- 비밀번호 찾기 기능이 추가되지 않았는지 확인합니다.

### 2.3 닉네임 변경

#### 1) 사용자가 무엇을 입력하거나 누르는지

- 로그인한 사용자가 계정 설정에서 새 닉네임을 입력합니다.
- 변경 버튼을 누릅니다.
- 닉네임의 앞뒤 공백은 제거하며 공백만 입력하면 빈 입력으로 처리합니다.

#### 2) 정상적으로 처리되면 무엇이 저장되고 화면에 무엇이 보이는지

- 새 닉네임이 계정에 저장됩니다.
- 계정 설정 화면에 바뀐 닉네임이 보입니다.
- 공개 기록과 댓글에 작성자의 닉네임을 표시합니다. 닉네임을 변경하면 과거 공개 기록과 댓글에도 새 닉네임을 표시합니다.

#### 3) 잘못 입력하거나 처리에 실패하면 어떻게 되는지

- 다른 사용자가 이미 쓰고 있는 닉네임은 저장하지 않습니다.
- 닉네임은 2~20자이며 한글, 영문, 숫자, 밑줄만 사용할 수 있습니다.
- 변경에 실패하면 실패 이유를 알려주고 입력한 새 닉네임을 유지합니다.

#### 4) 누가 보거나 수정·삭제할 수 있는지

- 로그인한 사용자는 자신의 닉네임만 변경할 수 있습니다.
- 다른 사용자의 닉네임은 변경할 수 없습니다.

#### 5) 나중에 제대로 만들었는지 어떻게 확인하면 되는지

- 사용하지 않은 닉네임으로 변경되는지 확인합니다.
- 이미 사용 중인 닉네임으로 변경되지 않는지 확인합니다.
- 닉네임의 길이와 허용 문자 규칙이 적용되는지 확인합니다.
- 닉네임을 변경하면 과거 공개 기록과 댓글에도 새 닉네임이 보이는지 확인합니다.
- 다른 사용자의 닉네임을 변경할 수 없는지 확인합니다.

## 3. 공개·비공개 기능

### 3.1 기록 공개 범위 설정

#### 1) 사용자가 무엇을 입력하거나 누르는지

- 공부 기록, 할 일 또는 오류 기록을 만들거나 수정할 때 공개 여부를 선택합니다.
- 공개 여부를 따로 선택하지 않으면 비공개가 기본값입니다.

#### 2) 정상적으로 처리되면 무엇이 저장되고 화면에 무엇이 보이는지

- 선택한 공개 여부가 기록과 함께 저장됩니다.
- 비공개 기록은 작성자 자신의 기록 화면에서 볼 수 있습니다.
- 공개 기록은 로그인한 다른 사용자도 공개 기록 화면에서 볼 수 있습니다.

#### 3) 잘못 입력하거나 처리에 실패하면 어떻게 되는지

- 공개 여부 변경에 실패하면 기존 공개 상태를 유지하고 실패 이유를 알려줍니다.
- 공개 기록을 비공개로 바꾸면 기존 댓글과 좋아요를 삭제하지 않고 다른 사용자에게 숨깁니다. 다시 공개하면 댓글과 좋아요를 다시 보여줍니다.
- 신고 기록은 공개 여부와 관계없이 운영자만 계속 확인할 수 있습니다.

#### 4) 누가 보거나 수정·삭제할 수 있는지

- 기록 작성자만 자신의 기록 공개 여부를 바꿀 수 있습니다.
- 작성자만 자신의 비공개 기록을 볼 수 있습니다.
- 로그인한 사용자는 다른 사용자의 공개 기록을 볼 수 있습니다.
- 로그인하지 않은 사용자는 공개 기록도 볼 수 없습니다.

#### 5) 나중에 제대로 만들었는지 어떻게 확인하면 되는지

- 새 기록이 기본적으로 비공개인지 확인합니다.
- 작성자가 공개로 바꾸면 다른 로그인 사용자에게 보이는지 확인합니다.
- 다시 비공개로 바꾸면 다른 사용자에게 보이지 않는지 확인합니다.
- 비공개로 바꾼 기록의 댓글과 좋아요가 숨겨지고, 다시 공개하면 나타나는지 확인합니다.
- 기록이 비공개가 되어도 운영자가 신고 기록을 확인할 수 있는지 확인합니다.
- 로그인하지 않은 상태에서는 공개 기록도 볼 수 없는지 확인합니다.

## 4. 공부 기록

### 4.1 공부 기록 만들기

#### 1) 사용자가 무엇을 입력하거나 누르는지

- 1~100자의 제목을 입력합니다.
- 1~5,000자의 내용을 입력합니다.
- 공개 또는 비공개를 선택합니다. 선택하지 않으면 비공개입니다.
- 저장 버튼을 누릅니다.

#### 2) 정상적으로 처리되면 무엇이 저장되고 화면에 무엇이 보이는지

- 제목, 내용, 공개 여부, 작성자, 작성 날짜와 시간이 저장됩니다.
- 저장한 기록은 작성자의 공부 기록 목록에 나타납니다.
- 목록에서는 최근에 작성한 기록부터 보여줍니다.
- 저장에 성공하면 공부 기록 목록 화면으로 이동합니다.

#### 3) 잘못 입력하거나 처리에 실패하면 어떻게 되는지

- 제목이 없거나 100자를 넘으면 저장하지 않습니다.
- 내용이 없거나 5,000자를 넘으면 저장하지 않습니다.
- 제목과 내용의 앞뒤 공백은 제거하고 중간 띄어쓰기는 유지합니다. 공백만 입력하면 빈 입력으로 처리합니다.
- 저장에 실패하면 실패 이유를 알려주고 작성 중인 제목과 내용을 유지합니다.

#### 4) 누가 보거나 수정·삭제할 수 있는지

- 작성자는 자신의 공부 기록을 볼 수 있습니다.
- 비공개 기록은 작성자만 볼 수 있습니다.
- 공개 기록은 로그인한 다른 사용자도 볼 수 있습니다.
- 수정과 삭제는 작성자만 할 수 있습니다.

#### 5) 나중에 제대로 만들었는지 어떻게 확인하면 되는지

- 제목 1자와 100자, 내용 1자와 5,000자로 저장되는지 확인합니다.
- 제목 0자와 101자, 내용 0자와 5,001자가 저장되지 않는지 확인합니다.
- 작성 날짜와 시간이 자동으로 저장되는지 확인합니다.
- 새 기록이 기본적으로 비공개인지 확인합니다.
- 제목과 내용의 앞뒤 공백이 제거되고 중간 띄어쓰기는 유지되는지 확인합니다.
- 저장 실패 시 작성 중인 제목과 내용이 남는지 확인합니다.
- 저장 성공 후 공부 기록 목록으로 이동하는지 확인합니다.

### 4.2 공부 기록 목록·읽기·검색

#### 1) 사용자가 무엇을 입력하거나 누르는지

- 자신의 공부 기록 목록을 엽니다.
- 목록에서 기록을 눌러 자세한 내용을 읽습니다.
- 검색어를 입력해 내 공부 기록을 검색합니다.
- 검색어의 앞뒤 공백은 제거하며 공백만 입력하면 빈 검색어로 처리합니다.

#### 2) 정상적으로 처리되면 무엇이 저장되고 화면에 무엇이 보이는지

- 목록에 자신의 공부 기록이 최근 작성 순서로 보입니다.
- 기록을 선택하면 저장된 제목과 내용이 보입니다.
- 검색하면 제목이나 내용에 검색어가 포함된 내 공부 기록이 보입니다.
- 검색은 기록을 새로 저장하지 않습니다.

#### 3) 잘못 입력하거나 처리에 실패하면 어떻게 되는지

- 검색어가 비어 있으면 전체 공부 기록 목록을 보여줍니다.
- 목록·상세·검색을 불러오지 못하면 실패 안내를 보여주고 저장된 데이터는 바꾸지 않습니다.

#### 4) 누가 보거나 수정·삭제할 수 있는지

- 사용자는 자신의 공개·비공개 공부 기록을 모두 볼 수 있습니다.
- 다른 사용자는 공개된 공부 기록만 볼 수 있습니다.
- 내 공부 기록 검색 결과는 작성자 본인만 볼 수 있습니다.

#### 5) 나중에 제대로 만들었는지 어떻게 확인하면 되는지

- 여러 기록을 저장한 뒤 최근 기록이 먼저 나오는지 확인합니다.
- 제목에 있는 단어와 내용에 있는 단어로 각각 검색되는지 확인합니다.
- 다른 사용자의 비공개 공부 기록이 목록이나 검색에 나타나지 않는지 확인합니다.

### 4.3 공부 기록 수정·삭제

#### 1) 사용자가 무엇을 입력하거나 누르는지

- 작성자가 자신의 공부 기록에서 수정 또는 삭제를 누릅니다.
- 수정할 때 제목, 내용, 공개 여부를 바꾸고 저장합니다.

#### 2) 정상적으로 처리되면 무엇이 저장되고 화면에 무엇이 보이는지

#### 4) 누가 보거나 수정·삭제할 수 있는지

- 작성자는 자신의 오류 기록을 볼 수 있습니다.

- 해결 상태를 다시 미해결로 바꿀 수 있습니다. 해결 방법은 유지하고 해결 날짜와 시간은 지웁니다.
- 수정 또는 삭제에 실패하면 기존 오류 기록을 바꾸지 않고 실패 이유를 알려줍니다. 수정 중인 입력값도 유지합니다.
- 삭제 전에 확인창을 보여주며 사용자가 동의한 경우에만 삭제합니다.

#### 4) 누가 보거나 수정·삭제할 수 있는지

- 작성자만 자신의 오류 기록을 해결 처리하거나 수정·삭제할 수 있습니다.
- 다른 사용자는 공개 오류 기록을 읽을 수 있어도 바꿀 수 없습니다.

#### 5) 나중에 제대로 만들었는지 어떻게 확인하면 되는지

- 해결 방법을 입력한 뒤 해결 상태로 바뀌는지 확인합니다.
- 해결 날짜와 시간이 자동으로 저장되는지 확인합니다.
- 해결 방법이 없으면 해결 상태로 바뀌지 않는지 확인합니다.
- 해결 상태를 취소하면 해결 방법은 남고 해결 날짜와 시간은 지워지는지 확인합니다.
- 수정 날짜와 시간이 저장되어 상세 화면에 보이는지 확인합니다.
- 수정 성공 후 오류 기록 목록으로 이동하는지 확인합니다.
- 삭제 확인에 동의하지 않으면 오류 기록이 삭제되지 않는지 확인합니다.
- 다른 사용자가 수정·삭제하거나 해결 상태를 바꿀 수 없는지 확인합니다.

## 7. 공개 기록

### 7.1 공개 기록 목록·필터·검색

#### 1) 사용자가 무엇을 입력하거나 누르는지

- 로그인한 사용자가 공개 기록 화면을 엽니다.
- 공부 기록, 할 일, 오류 기록 중 하나를 눌러 나누어 봅니다.
- 검색어를 입력해 공개 기록을 검색합니다.
- 검색어의 앞뒤 공백은 제거하며 공백만 입력하면 빈 검색어로 처리합니다.

#### 2) 정상적으로 처리되면 무엇이 저장되고 화면에 무엇이 보이는지

- 공개된 공부 기록, 할 일, 오류 기록이 보입니다.
- 종류를 선택하면 해당 종류의 공개 기록만 보입니다.
- 검색 결과에는 공개 기록만 나타납니다.
- 공개 공부 기록은 제목과 내용, 공개 할 일은 제목, 공개 오류 기록은 오류 제목·오류 내용·해결 방법에서 검색합니다.
- 공개 기록은 최근에 작성한 기록부터 보여줍니다.

#### 3) 잘못 입력하거나 처리에 실패하면 어떻게 되는지

- 검색어가 비어 있으면 전체 공개 기록 목록을 보여줍니다.
- 공개 목록·필터·검색을 불러오지 못하면 실패 안내를 보여주고 저장된 데이터는 바꾸지 않습니다.

#### 4) 누가 보거나 수정·삭제할 수 있는지

- 로그인한 사용자는 다른 사용자의 공개 기록을 볼 수 있습니다.
- 로그인하지 않은 사용자는 공개 기록을 볼 수 없습니다.
- 공개 기록의 수정·삭제는 해당 기록의 작성자만 할 수 있습니다.

#### 5) 나중에 제대로 만들었는지 어떻게 확인하면 되는지

- 세 종류의 공개 기록이 공개 화면에 나타나는지 확인합니다.
- 종류별 필터가 맞는 기록만 보여주는지 확인합니다.
- 검색 결과에 비공개 기록이 섞이지 않는지 확인합니다.
- 공부 기록은 제목·내용, 할 일은 제목, 오류 기록은 오류 제목·내용·해결 방법으로 검색되는지 확인합니다.
- 빈 검색어로 검색하면 전체 공개 기록이 보이는지 확인합니다.
- 공개 기록이 최근 작성 순서로 보이는지 확인합니다.
- 로그인하지 않은 상태에서 공개 화면을 볼 수 없는지 확인합니다.

## 8. 댓글

### 8.1 댓글 작성·수정·삭제

#### 1) 사용자가 무엇을 입력하거나 누르는지

- 로그인한 사용자가 공개된 공부 기록 또는 오류 기록을 엽니다.
- 1~500자의 댓글을 입력하고 등록 버튼을 누릅니다.
- 자신의 댓글에서 수정 또는 삭제를 누를 수 있습니다.
- 기록 작성자는 자신의 공개 기록에 달린 댓글을 삭제할 수 있습니다.

#### 2) 정상적으로 처리되면 무엇이 저장되고 화면에 무엇이 보이는지

- 댓글 내용, 댓글 작성자, 댓글이 달린 기록이 저장됩니다.
- 등록한 댓글이 해당 공개 기록에 보입니다.
- 수정하면 바뀐 댓글 내용이 보입니다.
- 삭제하면 해당 댓글이 더 이상 보이지 않습니다.
- 댓글은 오래된 댓글부터 보여줍니다.

#### 3) 잘못 입력하거나 처리에 실패하면 어떻게 되는지

- 댓글이 없거나 500자를 넘으면 등록하지 않습니다.
- 댓글의 앞뒤 공백은 제거하고 중간 띄어쓰기는 유지합니다. 공백만 입력하면 빈 입력으로 처리합니다.
- 댓글 등록·수정·삭제에 실패하면 실패 이유를 알려줍니다. 등록·수정 중인 댓글은 유지하고 기존 저장 내용은 바꾸지 않습니다.
- 공개 기록이 비공개로 바뀌면 기존 댓글을 삭제하지 않고 다른 사용자에게 숨깁니다. 다시 공개하면 댓글을 다시 보여줍니다.

#### 4) 누가 보거나 수정·삭제할 수 있는지

- 로그인한 사용자만 공개된 공부 기록과 오류 기록의 댓글을 볼 수 있습니다.
- 로그인한 사용자는 해당 기록에 댓글을 작성할 수 있습니다.
- 댓글 작성자는 자신의 댓글을 수정·삭제할 수 있습니다.
- 기록 작성자는 자신의 기록에 달린 댓글을 삭제할 수 있습니다.
- 공개된 할 일에는 댓글을 작성할 수 없습니다.
- 첫 버전에서는 댓글에 답글을 달 수 없습니다.

#### 5) 나중에 제대로 만들었는지 어떻게 확인하면 되는지

- 공부 기록과 오류 기록에는 댓글을 등록할 수 있는지 확인합니다.
- 공개된 할 일에는 댓글 기능이 없는지 확인합니다.
- 1자와 500자 댓글은 등록되고 0자와 501자는 등록되지 않는지 확인합니다.
- 댓글 작성자와 기록 작성자의 삭제 권한이 맞는지 확인합니다.
- 다른 사용자의 댓글을 권한 없이 수정할 수 없는지 확인합니다.
- 댓글이 오래된 순서로 보이는지 확인합니다.
- 댓글의 앞뒤 공백이 제거되고 공백만 입력한 댓글은 등록되지 않는지 확인합니다.
- 댓글 삭제 확인에 동의하지 않으면 삭제되지 않는지 확인합니다.
- 기록을 비공개로 바꾸면 댓글이 숨겨지고 다시 공개하면 나타나는지 확인합니다.

#### 1) 사용자가 무엇을 입력하거나 누르는지

- 사용자는 자신이 누른 좋아요만 취소할 수 있습니다.
- 공개된 할 일에는 좋아요 기능을 제공하지 않습니다.

#### 5) 나중에 제대로 만들었는지 어떻게 확인하면 되는지

- 같은 기록에 처음 누르면 좋아요 상태가 되는지 확인합니다.
- 다시 누르면 취소되는지 확인합니다.
- 같은 사용자의 좋아요가 중복 저장되지 않는지 확인합니다.
- 공개된 할 일에 좋아요 기능이 없는지 확인합니다.
- 전체 좋아요 수가 보이는지 확인합니다.
- 기록을 비공개로 바꾸면 좋아요와 개수가 숨겨지고 다시 공개하면 나타나는지 확인합니다.

#### 5) 나중에 제대로 만들었는지 어떻게 확인하면 되는지

- 로그인한 사용자가 공개 기록을 신고할 수 있는지 확인합니다.
- 로그인한 사용자가 댓글을 신고할 수 있는지 확인합니다.
- 신고 정보가 운영자 확인용으로 저장되는지 확인합니다.
- 신고 직후 대상 기록이나 댓글이 자동 삭제되지 않는지 확인합니다.
- 신고 이유 1자와 500자는 저장되고 0자와 501자는 저장되지 않는지 확인합니다.
- 같은 사용자가 같은 대상을 두 번 신고할 수 없는지 확인합니다.
- 신고 성공과 실패 안내가 보이고 실패 시 신고 이유가 남는지 확인합니다.

- React에서 화면, 입력값, 화면 이동을 처리합니다.
- FastAPI에서 입력 조건, 로그인 상태, 작성자와 운영자 권한을 검사하고 데이터를 저장합니다.
- React는 FastAPI에 요청하며, 서버가 보내는 결과에 따라 성공 화면이나 실패 안내를 보여줍니다.
- 화면에서 버튼을 숨기는 것과 별도로 FastAPI에서도 모든 조회·변경 요청의 권한을 검사합니다.
- 운영·로컬 실행 데이터는 Supabase의 PostgreSQL에 저장합니다. 백엔드 `backend/.env`에서 Session pooler 연결 정보를 읽으며 설정 누락 시 SQLite3로 대체하지 않습니다. 자동 테스트만 별도 임시 SQLite3를 사용합니다. 기존 SQLite3 데이터는 보존하고 이번 변경에서 이전하지 않습니다.
- Supabase는 DB 용도로 사용합니다. 회원과 로그인 기능은 FastAPI에서 처리하며 Supabase Auth 등 별도 서비스는 자동으로 추가하지 않습니다.
- DB 연결 비밀번호와 서버 비밀값은 React에 전달하지 않습니다.

### 14.2 신고 확인

- 운영자는 전용 React 화면에서 FastAPI에 신고 목록과 내용을 요청해 확인합니다.
- FastAPI는 운영자 권한을 확인한 경우에만 신고 데이터를 응답합니다.
- 일반 사용자가 운영자 화면이나 API 주소로 직접 접근해도 신고 내용을 볼 수 없어야 합니다.
- 신고 확인만 제공하며 별도의 처리 상태나 자동 삭제 기능은 만들지 않습니다.

### 14.3 개발·테스트 확인

- SQLite3에서도 앞서 정한 입력 조건, 중복 방지, 상태 전환과 권한 규칙을 확인합니다.
- 자동 테스트는 실행 중인 개발 DB 및 운영 DB와 분리된 SQLite3 DB를 사용합니다.
- Supabase 연결 준비가 되면 별도 검증용 데이터로 DB 구조 변경, 데이터 저장·조회, 검색, 날짜, 중복 방지와 권한 검사를 확인합니다.
- SQLite3 테스트만 통과한 상태와 Supabase 연결까지 확인한 상태를 구분해 기록합니다.
- React 화면의 성공·실패 안내, 입력 유지와 이동 경로는 이 문서의 기존 규칙을 그대로 따릅니다.

## 15. 확장 기능: 비공개 학습 자료함

이 절은 기존 MVP와 별개로 추가한 요구사항입니다. M1~M5에서 `/materials` 입력·파일 선택과 등록·목록·원본 보기·삭제 API 연결을 구현했고 예시 목록을 제거했습니다. 실제 FastAPI와 분리된 임시 SQLite/파일 폴더·Chrome에서 전체 흐름을 검증했습니다. 실제 Supabase 적용·권한·저장은 아직 미검증입니다. 아래 동작의 전체 완료 기준과 상세 API·테이블·실패 복구 설계는 [학습 자료함 개발 계획](materials-plan.md)을 따릅니다.

### 15.1 들어가기와 권한

- 기존 홈의 학습 자료함 링크나 `/materials`로 들어갑니다. 공통 AuthProvider와 기존 로그인 보호를 유지합니다.
- 모든 자료 API에서 기존 `current_user`/`CurrentUser`(요청의 `get_current_user` 역할)를 사용합니다. 등록·삭제에는 기존 CSRF·Origin 검사도 적용합니다.
- 본인 자료만 볼 수 있습니다. 작성자를 요청값으로 정하지 않습니다. 다른 작성자의 자료 ID로 원본·삭제 요청을 보내도 자료 없음(404)으로 처리합니다. 비로그인은 401이며 화면은 기존 로그인 흐름을 따릅니다.

### 15.2 파일 선택과 등록

1. 제목과 선택 메모를 입력하고 파일 한 개를 선택합니다. 제목은 앞뒤 공백 제거 후 1~100자, 메모는 최대 1,000자입니다. 제목의 내부 공백은 보존하고 빈 메모는 미입력으로 취급합니다.
2. PNG·JPG/JPEG는 최대 5MiB(5,242,880바이트), MP4는 최대 30MiB(31,457,280바이트)입니다. 한도와 같은 크기는 허용합니다. 빈 파일·여러 파일·지원하지 않는 형식·실제 형식이 다른 위장 파일은 거절합니다.
3. 화면에 선택 파일명·종류·용량과 입력 오류를 보여줍니다. 프론트 검사와 별도로 서버에서도 글자 수·파일 개수·실제 형식·실제 바이트 수를 검사합니다.
4. 업로드를 누르면 기존 로그인 쿠키와 CSRF 정보를 사용해 FormData로 보냅니다. 처리 중 중복 클릭을 막고 파일·DB 저장이 모두 성공한 경우만 성공을 안내합니다.
5. 성공하면 입력과 파일 선택을 비우고 실제 목록에 반영합니다. 실패하면 가능한 입력·파일 선택과 기존 목록을 유지하며 이유를 안내합니다. 업로드 실패·시간 초과 후 자동 재전송하지 않습니다.
6. 파일 저장 실패·DB 실패·취소 시 이번 요청이 만든 임시 파일과 메타정보를 정리합니다. 실패한 자료를 저장 완료로 표시하지 않습니다.

### 15.3 목록과 원본 보기

- 본인 자료만 최신 등록순으로 표시합니다. 같은 등록 시각은 ID 역순으로 정렬합니다. 제목·메모·파일명·종류·용량·등록일을 보여주고 전체·이미지·영상 필터와 개수를 실제 목록에 맞춥니다.
- 로딩 중, 빈 목록, 조회 실패와 재시도를 구분합니다. 실패를 빈 목록이나 디자인 예시로 대체하지 않습니다.
- 원본 보기마다 서버가 로그인과 작성자를 확인합니다. 이미지·영상의 실제 원본 바이트를 응답하며 파일 저장 경로나 공개 정적 URL은 노출하지 않습니다.
- 없는 자료·다른 작성자의 자료·원본이 유실된 자료는 원본 보기 404로 안내합니다. 브라우저 재생 가능 여부와 별개로 저장된 원본을 변환하지 않습니다.

### 15.4 삭제

- 삭제 확인 후 요청합니다. 취소하면 아무것도 바뀌지 않습니다. 본인 자료에만 삭제와 CSRF 검사를 적용합니다.
- 정상 삭제하면 메타정보와 원본을 정리하고 목록·필터 개수를 갱신합니다. 원본만 이미 없다면 본인 메타정보는 삭제할 수 있습니다.
- 파일 이동 실패나 DB 삭제 실패 시 성공으로 안내하지 않고 가능한 기존 상태로 복구합니다. DB 커밋 후 남은 임시 보관 파일은 내부 정리 대상으로 다룹니다. 구체적인 보상 순서는 개발 계획 4절을 따릅니다.
- 이미 삭제되어 404인 경우 현재 상태를 안내하고 목록을 재조회합니다. 네트워크·서버 실패 시 카드를 임의로 지우지 않습니다.

### 15.5 화면과 검증 기준

- 기존 독립 페이지와 전용 스타일을 유지합니다. 작은 화면에서 등록 폼과 목록을 세로로 배치합니다. 기존 홈·대시보드·로그인·기록 기능은 보존합니다.
- 실제 API 연결 전까지 디자인 예시 표시와 미연결 안내를 유지합니다. 실제 연결 후 예시를 제거하며 AI 영역은 연결 예정 상태로 남깁니다.
- 제목·메모 경계값, 파일 제한값과 초과값, 위장 파일, 두 사용자의 접근 분리, CSRF, 저장/삭제 실패 복구, 새로고침 후 유지, 모바일 화면과 기존 인증 회귀를 테스트합니다.
- 실행은 Supabase PostgreSQL, 자동 테스트는 임시 DB·임시 업로드 폴더로 분리합니다. 실제 Supabase 검증 여부를 따로 보고합니다. 실제 업로드 파일은 Git에 포함하지 않습니다.

## 16. 추가 확장 계획: AI 요약 동작

다음은 앞선 보관 기능 M1~M5와 구분하는 별도 확장입니다. AI1~AI6의 실행 코드·설정·모의 통합 검증을 완료했고 Supabase 컬럼을 적용했습니다. 실제 유료 호출·모델 품질은 키 입력 후 검증합니다. [개발 계획](materials-ai-plan.md)과 [실행 안내](materials-ai-setup.md)를 함께 확인합니다.

1. 사용자가 기존 방식으로 자료를 저장합니다. 파일·메타정보 저장 실패 시 OpenAI는 호출하지 않습니다.
2. 저장 성공 후 같은 자료에 분석 대기 상태를 기록하고 내부 작업자가 자동 분석을 시작합니다. 별도 분석 시작 버튼·워커 실행 명령은 요구하지 않습니다.
3. 이미지는 실제 내용을 보고, 영상은 최대 8장의 시간순 대표 화면으로 한국어 요약을 생성합니다. 영상 음성은 제외하며 화면 기준 분석임을 표시합니다.
4. 검증된 결과는 materials의 요약 컬럼에 저장합니다. 제목·사용자 메모·원본은 덮어쓰지 않습니다. 재조회·새로고침 후에도 요약을 보여줍니다.
5. 화면에서 파일 저장/분석 중/요약 완료/분석 실패를 구분합니다. 실패하면 원본은 유지하며 쉬운 이유를 안내하고 작성자의 제한된 재분석 요청을 지원하는 안을 사용합니다.
6. API 키 누락·권한·잔액·타임아웃·출력 오류를 구분하고 비밀값은 출력하지 않습니다. 비싼 모델이나 중복 유료 요청으로 자동 전환하지 않습니다.
7. 분석 도중 삭제하면 자료를 되살리지 않습니다. 서버 중단·불확실한 외부 결과를 무조건 자동 재호출하지 않습니다. 요약·상태·재분석도 본인 권한과 CSRF 기준을 따릅니다.
8. 업로드 전에 분석용 이미지/프레임의 외부 전송을 안내합니다. 사용자가 선택한 시각 요약 외에 음성 전사·검색·이미지 생성·과거 자료 일괄 분석은 추가하지 않습니다.

구체적인 상태 전환, API 계약, 삭제·재시작 처리, UI 폴링 및 검증은 [AI 요약 SDD](materials-ai-sdd.md)를 따릅니다. GET `/api/materials/{id}/analysis`와 POST `/api/materials/{id}/analysis/retry`를 구현했으며 본인 권한·재시도 CSRF를 적용합니다. 기존 목록/저장 응답의 analysis에도 요약·상태를 포함합니다.
